# L8, m=2 fixed-target screen

This is a single paired NTP/auxiliary screen for the long-context RHM
calibration. It uses one grammar seed and one model seed. The NTP arm and all
auxiliary arms are generated by `sweep_target_depth.py` from the same sampled
grammar and data pools and the same backbone initialization.

## Frozen configuration

- RHM: `v=n=16`, `m=2`, `s=2`, `L=8`.
- Leaf sequence length: `2^8 = 256`.
- Transformer: 8 layers, 8 heads, width 256, zero dropout.
- Arms: NTP, then fixed next-latent targets `j=0, 2, 4, 8`.
- Auxiliary weight: `lambda=1.0` for each target arm.
- Training pool: 65,536 sequences, resampled each epoch.
- Fixed validation/test pools: 16,384 sequences each.
- Batch size: 32.
- AdamW, learning rate `3e-4`, betas `(0.9, 0.95)`, no weight decay or warmup.
- Gradient clipping: `1.0`.
- 5,000 optimizer updates.
- Validation and probes every 100 updates.
- No model checkpoints by default.
- MPS with fallback disabled.

Batch 32 gives 8,160 predicted tokens per update, close to the 7,936 tokens
per update in the L5/batch-256 reference. Five thousand updates therefore gives
160,000 sequence draws and approximately 40.8 million predicted-token
exposures. The primary analysis targets H1--H7; the root level is not a normal
probe target.

## Run the paired study

From the repository root:

```bash
set -e
screen=experiments/02_fixed_latent_targets/runs/target_depth_l8_m2_lambda_1_0_5000_updates
config=experiments/02_fixed_latent_targets/configs/target_depth_screen_l8_m2_lambda_1_0.json
PYTORCH_ENABLE_MPS_FALLBACK=0 .venv/bin/python -u sweep_target_depth.py \
  --config "$config" --output-dir "$screen" --resume
```

The five arms are `ntp`, `target_0`, `target_2`, `target_4`, and `target_8`.
The `target_8` arm is valid: it predicts the next position's detached final
residual stream from the current final residual stream.

## Primary diagnostics

Probes run at each validation event. After all five arms finish, summarize
their validation histories:

```bash
set -e
screen=experiments/02_fixed_latent_targets/runs/target_depth_l8_m2_lambda_1_0_5000_updates
.venv/bin/python summarize_target_depth.py \
  --screen-dir "$screen" \
  --rule experiments/02_fixed_latent_targets/acquisition_rule.json \
  --levels 3 4 5 6 7 \
  --output-dir "$screen/analysis"
.venv/bin/python plot_trajectory.py \
  --comparison "$screen/analysis/comparison.json" \
  --output-dir "$screen/analysis/plots"
```

The full probe trajectory measures H1--H7 at every 100-update validation event.
The primary event is balanced accuracy `0.75` at two consecutive observations;
50/75/90% milestones use the same persistence rule. C/Q and shuffled-label
controls remain separate supporting analyses and are not acquisition hurdles.
Offline controls require explicitly saved continuation checkpoints.

## Interpretation gate

The useful outcome is an ordered and reproducible progression across H3--H7,
not a one-block-per-level mapping. H7 need not be fully saturated, but its
curve should show movement above chance if the L8/m=2 regime is to support a
deeper developmental experiment. Absolute tau values are not directly
comparable with the L5/m=4 study because both hierarchy depth and synonym
count changed.
